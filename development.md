# MyLedger

MyLedger is a web interface for [hledger](https://hledger.org/) built with FastAPI.

It provides a browser-based interface for viewing and managing personal financial data stored in hledger journals. This document helps me keep up with my workflow for making changes. If you do everything exactly like I do, this doc should be a guide.

## Requirements

- Python 3.13+
- hledger
- Git
- A virtual environment (`.venv`)
- A browser

The production deployment currently runs on a Linux VM.

# Local Development

Local development is currently done on Windows using VS Code. These steps let you set up a local server to see live updates of changes before commiting them to your main instance.

## 1. Clone the repository

```powershell
git clone git@github.com:justbennett/myledger.git
cd myledger
```

If the repository is already cloned:

```powershell
git pull origin main
```

## 2. Create the virtual environment


```powershell
python -m venv .venv
```

Activate it if desired:

```powershell
.\.venv\Scripts\Activate.ps1
```

The commands below can also explicitly use `.venv\Scripts\python.exe` without activating the environment.

## 3. Install dependencies

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 4. Configure local environment variables

Copy `.env.example` to `.env`.

```powershell
Copy-Item .env.example .env
```

Edit `.env` and provide values for:

```text
MYLEDGER_USERNAME=your_username
MYLEDGER_PASSWORD_HASH=your_password_hash
MYLEDGER_SESSION_SECRET=your_random_session_secret
```

The `.env` file contains secrets and **must not be committed to Git**.

Optionally set `MYLEDGER_DATA_DIR` to the directory containing the `journals/` and `rules/` folders. If unset, it defaults to the directory from which the application is run.

Generate a session secret with:

```powershell
python -c "import secrets; print(secrets.token_hex(32))"
```

The password hash is a PBKDF2-HMAC-SHA256 hash generated by the project's password-generation procedure.

## 5. Run the application

```powershell
.\.venv\Scripts\python.exe -m uvicorn app:app --reload
```

Open:

```text
http://127.0.0.1:8000
```

The local development server uses the values in `.env`.

# Authentication

MyLedger uses session-based authentication.

The application requires:

- Username
- Password
- Session secret

Passwords are not stored as plaintext. The configured password is stored as a PBKDF2-HMAC-SHA256 hash with a random salt.

The session secret is used to sign the authentication session cookie.

## Environment Variables

| Variable | Purpose |
|---|---|
| `MYLEDGER_USERNAME` | Login username |
| `MYLEDGER_PASSWORD_HASH` | PBKDF2 password hash |
| `MYLEDGER_SESSION_SECRET` | Secret used to sign session cookies |
| `MYLEDGER_DATA_DIRECTORY`| Path for the user-data folder|

Do not commit actual values for these variables to Git.

# Production Deployment

My production instance runs on a Linux VM under Proxmox. This could also be run on a remote server, of course, but see the security note below.

Application directory:

```text
/home/justbennett/myledger
```

The application runs under Uvicorn and is managed by systemd.

## Production Environment File

Production secrets are stored outside the Git repository:

```text
/etc/myledger.env
```

Example structure:

```ini
MYLEDGER_USERNAME=your_username
MYLEDGER_PASSWORD_HASH=your_password_hash
MYLEDGER_SESSION_SECRET=your_random_session_secret
MYLEDGER_DATA_DIR=/home/root_username/myledger-data
```

The file should be protected:

```bash
sudo chmod 600 /etc/myledger.env
sudo chown root:root /etc/myledger.env
```

The systemd service loads this file automatically.

## Systemd Service

The service is:

```text
/etc/systemd/system/myledger.service
```

The service contents:

```text
[Unit]
Description=MyLedger FastAPI application
After=network.target

[Service]
User=root_username
WorkingDirectory=/home/root_username/myledger
ExecStart=/home/root_username/myledger/.venv/bin/uvicorn app:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=5
EnvironmentFile=/etc/myledger.env

[Install]
WantedBy=multi-user.target
```

After changing the service configuration:

```bash
sudo systemctl daemon-reload
```

Restart the application with:

```bash
sudo systemctl restart myledger
```

Check its status:

```bash
sudo systemctl status myledger
```

View recent logs:

```bash
sudo journalctl -u myledger -n 50 --no-pager
```

The service is configured to start automatically when the VM boots with:

```bash
sudo systemctl enable myledger
```

# Deploying Updates

The normal development workflow is:

```text
Windows / VS Code
        ↓
git commit
        ↓
git push origin main
        ↓
GitHub
        ↓
Linux VM
git pull origin main
        ↓
restart MyLedger
```

## Update the Production VM

On the VM:

```bash
cd ~/myledger
git pull origin main
```

Install/update Python dependencies:

```bash
source .venv/bin/activate
pip install -r requirements.txt
```

Then restart the application:

```bash
sudo systemctl restart myledger
```

Verify:

```bash
sudo systemctl status myledger
```

The production environment file at `/etc/myledger.env` is **not** stored in Git and does not need to be changed when normal application code is deployed.

# Git Workflow

The repository's `main` branch is the source-controlled version of the application. Normal development should happen in the local VS Code copy.

Before starting work:

```bash
git pull origin main
```

After making changes:

```bash
git status
git add .
git commit -m "Describe the change"
git push origin main
```

Then update the production VM with:

```bash
cd ~/myledger
git pull origin main
```

Avoid making application-code changes directly on the production VM. If an emergency production change is necessary, commit and push that change so the Git repository remains the source of truth.

### Deployment Script

To handle updates directly from the Data Management page you can add a deployment script at "/usr/local/bin/myledger-deploy" to the production environment. If you're interested in how to set that up let me know.
The /update-status route uses that script to check for updates and allow the user to pull any updates. If that script isn't present the route simply gives a message that the feature isn't available.

# Security Notes

MyLedger is currently intended for use on a trusted local network.

It should **not be exposed directly to the public Internet**.

Authentication protects the application, but LAN-only access remains an intentional part of the current deployment design.

Production secrets are stored outside the Git repository in:

```text
/etc/myledger.env
```

Local development secrets are stored in:

```text
.env
```

Both files are excluded from Git.

Never commit:

- Passwords
- Password hashes
- Session secrets
- `.env`
- Private SSH keys
- Personal financial data unless intentionally included in the repository
